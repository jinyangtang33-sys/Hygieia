# 观己 Mac 健康中转

先在终端指定你自己的私人站点，然后启动接收器：

```sh
SELFSPACE_SITE_URL="https://your-private-site.example" ./mac-bridge/启动健康中转.command
```

也可在本机终端会话中设置 `SELFSPACE_SITE_URL` 后启动。不要将实际站点凭据写进源码。默认示例域名不会连接原作者的站点。
需要 macOS 自带 Python 3、Xcode Command Line Tools，不需要 Docker 或 Python 第三方依赖。

1. 在观己「健康同步」页生成并复制 Mac 配置，粘贴到本机管理页。
2. 默认保存到 macOS 登录钥匙串。若系统询问钥匙串访问，请允许此本机组件使用。
3. iPhone 和 Mac 连接同一可信 Wi-Fi。在 PulsHealth → Sync → Database 扫描本机管理页二维码，测试连接并保存。
4. 睡眠选择 Raw Samples；步数、活动能量、运动选择 Daily total；心率、静息心率、HRV、呼吸选择 Daily average。所有汇总选择 1 day / All devices。手机采用北京时间。
5. 首次回填最近 7 天。保持手机解锁，手动启动同步。Mac 管理页同时出现接收和转发时间后，刷新观己。

Mac 需要保持唤醒且终端持续运行。停止时关闭终端或按 Ctrl-C，下次重新双击启动文件。
关机、休眠、离开同一网络会推迟手机同步，恢复条件后打开 App 补传。iOS 不保证实时后台投递。
如果 Mac 的局域网 IP 变化，更新手机接收地址或重新扫描配对，不必清空数据。
原始数据保存在项目中被 Git 和发布打包排除的 `.bridge-runtime/health.sqlite`。
凭据仅在内存及 macOS 钥匙串中，不写入数据库或配置文件。

PulsHealth 走免费自托管方式；不购买同步订阅。网站现有托管费用和额度仍以平台为准。
本机接收端口 8765 使用局域网 HTTP，只应在可信 Wi-Fi 使用，请勿设置公网端口转发。
本机数据文件依赖 macOS 账户和磁盘访问保护；本方案没有额外加密健康数据库。

网站只接收页面支持的每日指标。其他已授权原始数据会留在本机，不会被自动上传到其他服务。
每日步数等使用 Apple HealthKit 计算的 All devices 汇总，禁止直接叠加手机和手表的原始数量样本。
睡眠排除卧床、清醒时间，重叠睡眠区间取并集，连续夜间片段按醒来日期归档。
当前日界线固定北京时间；旅行跨时区时请重新检查汇总日期。

接收实现使用 PulsHealth 官方 Apache-2.0 参考接收器；离线二维码使用 Nayuki MIT 实现。
详见 `vendor/NOTICE.md`。依赖均随项目附带，不会把健康数据发送给二维码服务。
